01

What Phase 1 delivers

Today the NewsIntelligenceWorkflow returns a hardcoded placeholder string. After Phase 1, it fetches real articles from four technical sources every six hours, deduplicates them, stores title and summary in PostgreSQL, and makes them available via the existing feed endpoint. The frontend detail view shows real content instead of the placeholder message.

Phase 1 ingestion pipeline

Fetch

4 source activities run in parallel

RSS, GNews, HN, arXiv each return a list of ArticleCandidate

Merge

Candidates combined and deduplicated

SHA-256 of URL used as dedup key. Already-known URLs skipped.

Ingest

POST to internal .NET endpoint

Bearer auth. Backend persists new items, skips duplicates.

Serve

GET /api/v1/news/feed

Existing endpoint returns real articles ordered by date.

What stays the same

The public feed endpoint, the NewsV1Routes, the ListNewsFeedQueryHandler, and the NewsReadRepository are all untouched. Phase 1 only adds an ingestion path and extends the domain model. The feed gets better because the database gets real data — not because the read path changes.

02

Data contract — the shape of an article

The ArticleCandidate Pydantic model is the single shared shape that every source activity returns. The workflow merges these lists and hands them to the ingest activity, which maps them to the IngestNewsItemV1Request the backend expects. Keeping one canonical shape across all sources means the workflow never needs source-specific logic.

workers-platform / app / workflows / news_intelligence / contracts.py

from __future__ import annotations
from datetime import datetime
from typing import Literal
from pydantic import BaseModel, Field


class ArticleCandidate(BaseModel):
    """Normalised article shape returned by every source activity."""
    title: str
    url: str                          # canonical URL — used as dedup key
    source: str                        # human label e.g. "Hacker News", "arXiv"
    published_at: datetime | None = None
    summary: str = ""                  # RSS description / API snippet
    author: str | None = None
    source_feed_url: str | None = None  # which RSS feed it came from


class IngestNewsItemV1Request(BaseModel):
    """Mirrors the C# IngestNewsItemV1Request contract."""
    title: str
    url: str
    source: str
    body: str = ""
    author: str | None = None
    published_at: str | None = None  # ISO 8601
    source_feed_url: str | None = None


class IngestNewsItemV1Response(BaseModel):
    status: Literal["created", "duplicate"]
    id: str | None = None


class NewsIngestResult(BaseModel):
    created: int = 0
    duplicates: int = 0
    errors: int = 0

Body strategy

For Phase 1, summary is used as the article body — whatever the RSS feed or API provides (description, snippet, abstract). This is enough for Phase 2's embedding to work well. Full article scraping can be added later as a follow-up activity without changing any of the contracts defined here.

03

The four sources

All four are technical-only. Two require no API key. Two need one. The configuration for feed URLs and topic keywords lives in the worker settings so you can adjust it without touching code.

RSS feeds no key

feedparser — custom feed list

Fetches any RSS or Atom feed and normalises entries into ArticleCandidate. The list of feeds is configured in settings — add or remove URLs without code changes. Published date comes from the feed entry; summary from entry.summary or entry.description.

RSS_FEED_URLS = [ "https://hnrss.org/frontpage", "https://feeds.feedburner.com/ThePragmaticEngineer", "https://martinfowler.com/feed.atom", "https://blog.bytebytego.com/feed", "https://newsletter.pragmaticengineer.com/feed", # add your own… ]

Hacker News no key

HN Algolia API

Free public API — no key needed. Queries top stories filtered by a minimum score threshold (default 100 points) and number of comments. Returns title, URL, author, and creation timestamp. Summary is set to an empty string for now since HN doesn't provide article text — the title alone is enough for dedup and display.

HN_API_URL = "https://hn.algolia.com/api/v1/search" HN_MIN_SCORE = 100 HN_MAX_RESULTS = 30 # params: tags=story, numericFilters=points>{score}

GNews / NewsAPI API key

GNews API — topic queries

Queries GNews by a set of technical topic keywords. Returns articles with title, description (used as summary), source name, and published date. Free tier gives 100 requests/day — well within the 4x/day schedule. Falls back gracefully if the key is not set, logging a warning and returning an empty list.

GNEWS_API_KEY = env("GNEWS_API_KEY", default=None) GNEWS_TOPICS = [ "artificial intelligence", "machine learning", "software engineering", "developer tools", "startup technology", ] GNEWS_MAX_PER_TOPIC = 5

arXiv no key

arXiv API — CS categories

arXiv exposes a free Atom feed per category. Fetches recent papers from the categories you care about. Abstract is used as the summary — rich text, great for Phase 2 embeddings. Author is the first listed author. Results are filtered to the last 7 days to match the weekly run cadence.

ARXIV_CATEGORIES = [ "cs.AI", # Artificial Intelligence "cs.LG", # Machine Learning "cs.SE", # Software Engineering "cs.DC", # Distributed Computing "cs.AR", # Computer Architecture ] ARXIV_MAX_PER_CATEGORY = 10

Configuration approach

All source configuration (feed URLs, topic keywords, thresholds) should live in the existing Settings class in app/runtime/config/settings.py — the same pattern used for PLATFORM_INTERNAL_SERVICE_TOKEN and PLATFORM_API_BASE_URL. Feed lists can be environment variables as JSON strings, or a simple Python list in a config module. No database configuration needed for Phase 1.

04

Activities in detail

Six Temporal activities in total — four source fetchers, one deduplicator, and one ingest caller. Each is decorated with @activity.defn and registered in definitions.py. They follow the same error handling pattern as the existing run_nightly_memory_consolidation_activity: log, raise on unexpected errors, return structured data on success.

act 1
Python
fetch_rss_articles
activities.py · timeout 60s
▲

Behaviour

  • →Accepts feed_urls: list[str]. Loops over each URL and calls feedparser.parse(url). Uses asyncio.to_thread since feedparser is synchronous.
  • →For each entry: maps entry.title, entry.link, entry.summary or entry.description, entry.author, and entry.published_parsed to ArticleCandidate.
  • →Skips entries with no URL or no title. Logs a warning per skipped entry but never raises — a broken feed should not abort the whole workflow.
  • !Per-feed errors are caught individually. If one feed URL fails (timeout, 404), that feed is skipped and the others continue.

Signature

    feed_urls: list[str],
) -> list[ArticleCandidate]: ...

fetch_gnews_articles

Behaviour

  • →Accepts topics: list[str] and max_per_topic: int. Loops topics sequentially (to stay within rate limits) and calls GET https://gnews.io/api/v4/search?q={topic}&max={n}&token={key}&lang=en.

act 5
Python
ingest_articles
activities.py · timeout 120s
▼

Behaviour

  • →Accepts articles: list[ArticleCandidate]. For each article, builds an IngestNewsItemV1Request and POSTs to POST /api/internal/v1/news/items using Bearer auth from settings. Follows the exact pattern of run_nightly_memory_consolidation_activity.
  • →Sends requests concurrently using asyncio.gather with a concurrency cap (e.g. 10 at a time via a semaphore) to avoid overwhelming the backend with 50+ simultaneous POSTs.
  • →The backend responds with {"status": "created", "id": "..."}} or {"status": "duplicate"}. Tallies both into a NewsIngestResult and returns it.
  • !Per-article errors are logged and counted in result.errors but never raise. If 40 out of 50 articles succeed, the workflow still completes successfully.

Concurrency

  • →Use asyncio.Semaphore(10) to cap concurrent HTTP calls. This makes the activity safe regardless of how many candidates come in.
  • !A single httpx.AsyncClient instance is shared across all requests within the activity — avoids connection churn.
05

Workflow orchestration

The rewritten NewsIntelligenceWorkflow runs the four fetch activities in parallel, merges and deduplicates the results inside workflow code (no activity needed for this — it's just a Python set operation), then calls the ingest activity. Deduplication inside the workflow is safe because workflows in Temporal are deterministic — the set operation on URLs is pure Python with no side effects.

workers-platform / app / workflows / news_intelligence / workflow.py

from datetime import timedelta
from temporalio import workflow
from .contracts import ArticleCandidate, NewsIngestResult
from .activities import (
    fetch_rss_articles, fetch_hacker_news_articles,
    fetch_gnews_articles, fetch_arxiv_articles,
    ingest_articles,
)

@workflow.defn
class NewsIntelligenceWorkflow:

    @workflow.run
    async def run(self) -> NewsIngestResult:
        settings = workflow.unsafe.imports_passed_through()

        # Run all four source fetches in parallel
        results = await workflow.gather(
            workflow.execute_activity(
                fetch_rss_articles,
                settings.rss_feed_urls,
                start_to_close_timeout=timedelta(seconds=60)),
            workflow.execute_activity(
                fetch_hacker_news_articles,
                start_to_close_timeout=timedelta(seconds=30)),
            workflow.execute_activity(
                fetch_gnews_articles,
                settings.gnews_topics,
                start_to_close_timeout=timedelta(seconds=60)),
            workflow.execute_activity(
                fetch_arxiv_articles,
                settings.arxiv_categories,
                start_to_close_timeout=timedelta(seconds=60)),
            return_exceptions=True,  # one failed source doesn't abort all
        )

        # Merge + deduplicate by URL in workflow code (pure, no I/O)
        seen_urls: set[str] = set()
        unique: list[ArticleCandidate] = []
        for batch in results:
            if isinstance(batch, BaseException):
                continue  # source activity failed — skip
            for article in batch:
                if article.url not in seen_urls:
                    seen_urls.add(article.url)
                    unique.append(article)

        # Ingest into .NET backend
        return await workflow.execute_activity(
            ingest_articles,
            unique,
            start_to_close_timeout=timedelta(seconds=120),
        )

return_exceptions=True

Passing return_exceptions=True to workflow.gather means a failed fetch activity (network error, bad API response) returns an exception object instead of raising. The workflow checks for isinstance(batch, BaseException) and skips that source. This means GNews being down never blocks HN or arXiv from coming through.

Backend changes

Three things change in the .NET backend: the NewsItem domain entity gets body and URL fields, a new internal endpoint accepts ingest requests from the worker, and a migration adds the columns plus a unique index on URL hash for fast deduplication.

Platform.Domain / Features / News / NewsItem.cs — extended

namespace Platform.Domain.Features.News;

public sealed class NewsItem
{
    public string Id { get; set; } = "";
    public string Title { get; set; } = "";
    public string Source { get; set; } = "";
    public DateTimeOffset PublishedAt { get; set; }

    // — new in Phase 1 —
    public string Url { get; set; } = "";
    public string UrlHash { get; set; } = "";  // SHA-256 of Url — unique index
    public string Body { get; set; } = "";   // summary / abstract
    public string? Author { get; set; }
    public string? SourceFeedUrl { get; set; }
}

Platform.Api / Features / News / Internal / InternalNewsV1Routes.cs

using Platform.Application.Features.News.Ingest;
using Platform.Contracts.V1.News;
using Platform.Api.Middleware;

namespace Platform.Api.Features.News.Internal;

public static class InternalNewsV1Routes
{
    public static void Map(WebApplication app)
    {
        var group = app.MapGroup("/api/internal/v1/news")
            .WithTags("Internal News Worker");

        group.MapPost("items",
            async (
                IngestNewsItemV1Request body,
                IngestNewsItemCommandHandler handler,
                CancellationToken ct) =>
            {
                var result = await handler
                    .HandleAsync(new IngestNewsItemCommand(
                        body.Title, body.Url, body.Source,
                        body.Body, body.Author,
                        body.PublishedAt, body.SourceFeedUrl), ct)
                    .ConfigureAwait(false);
                return Results.Ok(result);
            })
            .DisableAntiforgery();
    }
}

Deduplication strategy

The IngestNewsItemCommandHandler computes SHA-256(url.ToLowerInvariant()), then checks if a row with that hash already exists using a fast index lookup. If found, it returns {"status": "duplicate"} without inserting. This is cheaper and more reliable than comparing URLs as strings (handles trailing slash differences, etc.). The unique index on UrlHash also prevents duplicates even under concurrent ingestion runs.

07

Scheduling

A Temporal schedule runs NewsIntelligenceWorkflow once a week, every Sunday at 22:00 UTC. Temporal schedules are persistent — they survive worker restarts and track missed runs. The schedule is registered automatically in code at worker startup via _ensure_schedules() in main.py — no CLI command needed.

Schedule

0 22 * * 0

Every Sunday at 22:00 UTC. All sources apply a 7-day age filter, so articles older than one week are discarded on ingest — matching the run cadence. The schedule ID is news-intelligence-weekly.

Code location

workers-platform/app/runtime/worker/main.py
→ _ensure_schedules()
→ _NEWS_SCHEDULE_ID = "news-intelligence-weekly"
→ _NEWS_CRON       = "0 22 * * 0"

overlap-policy Skip

Skip means if a scheduled run is still in progress when the next one is due, the new run is skipped rather than queued. The schedule is upserted on every worker restart — changing the cron in code and redeploying is all that is needed to update the schedule. The run is also triggerable manually from the Temporal UI without waiting for Sunday.
