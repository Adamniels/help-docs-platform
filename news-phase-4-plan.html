01

What Phase 4 delivers

After Phase 3 the system has one interest vector — a long-term profile that shifts slowly under momentum. This is good for stability but blind to two things: what you have been reading lately, and what you are actively working on right now.

Phase 4 adds two more dimensions to the ranking query. A short-term embedding — a raw snapshot of the last 14 days of behavior, no momentum — captures your current reading direction more aggressively than the long-term can. An active context embedding — derived from the projects and interests you have declared in your profile — injects deliberate signal about what is relevant to your current work. At feed time, all three are blended into a single query vector. The user does not change anything to benefit from this: active context is read directly from the existing profile fields.

Long-term (existing)
7-day interaction window, 0.85 momentum blend. Changes gradually across many runs. Represents your stable, durable interests. Untouched by Phase 4.
Short-term (new)
14-day interaction window, no momentum. Replaces itself completely on each run. Captures recent reading direction — a week of AI papers shifts this immediately.
Active context (new)
Embedding of declared interests and active project names from the user profile. Updated whenever the ingestion run fires. No interactions required.
02

How the blending works

All blending happens at read time inside NewsVectorSearch.RankByRelevanceAsync. Nothing changes about how profiles are written — each component is computed and stored independently. At the moment the feed is requested, the three stored vectors are combined into a single query vector and the existing cosine distance ranking runs unchanged.

The query vector formula

Weights are applied to whichever components are available. When a component is missing (no interactions yet, or no profile seeded) its weight is redistributed to the others proportionally so the result always sums to 1.0 before normalization.

70% long_term
20% short_term
10% active_context 
# Pseudocode — actual implementation is in C# in NewsVectorSearch

# Start with long-term (always present once profile is seeded)
query = 0.70 * long_term

# Add short-term if available (14-day behavioral snapshot)
if short_term is not None:
    query += 0.20 * short_term
else:
    query += 0.20 * long_term  # fall back to long-term

# Add active context if available (declared interests + projects)
if active_context is not None:
    query += 0.10 * active_context
else:
    query += 0.10 * long_term  # fall back to long-term

# Normalize to unit vector — then pass to cosine distance ranking
query = normalize(query)
ℹ
Graceful fallback. If neither short-term nor active context exists yet (e.g. first run, no interactions recorded), the query vector collapses to the long-term embedding. Phase 2 and Phase 3 behavior is preserved exactly. There is no error path for a missing component.

Short-term computation

The short-term uses the same weighting model as the long-term (dwell normalization, save weight 1.0, dismiss weight −0.3) but over a 14-day window and without the momentum blend. The result is the raw normalized weighted sum — it replaces the previous short-term value entirely on each run.

# Short-term — no momentum, raw weighted average of 14-day interactions
interactions = GetRecentAsync(userId, since=now - 14 days)
weighted_sum  = sum(weight_i * embedding_i)
short_term    = normalize(weighted_sum)   # stored directly, no blend

Active context computation

The active context is derived from the user's declared interests and active project names, read via the existing IUserInterestProvider. The same text-building logic used in SeedNewsProfileCommandHandler is reused — core interests, secondary interests, goals, and active project names are joined into a single text blob and embedded. This runs as a separate backend command triggered by a new worker activity on each ingestion cycle.

// Active context seed text — same structure as profile seeding
"Core interests: software engineering, AI systems\n"
"Secondary interests: embedded systems, distributed systems\n"
"Goals: backend internship, production-quality projects\n"
"Active projects: Platform, news feature"

// Embed → store as NewsUserProfile.ActiveContextEmbedding
// Updated every ingestion run — always fresh, no momentum
★
No new frontend work required. Active context reads from profile fields that already exist: CoreInterests, SecondaryInterests, Goals, and ActiveProjectsJson. If you later add per-project topic lists, the active context embedding automatically becomes more specific — Phase 4 is already wired for it.

Backend changes

1. Extend UpdateNewsProfileCommandHandler — compute short-term in one pass

The handler already reads interactions and computes the long-term blend. Phase 4 adds a second computation in the same method: fetch 14 days of interactions (a superset of the existing 7-day window), compute the raw weighted average over the full 14 days, normalize it, and store it as ShortTermEmbedding. One DB round-trip for interactions, two outputs.

public async Task<UpdateNewsProfileResult> HandleAsync(
    UpdateNewsProfileCommand command, CancellationToken ct)
{
    // Fetch 14-day window — superset that covers both long-term (7d) and short-term (14d)
    var since14 = DateTimeOffset.UtcNow.AddDays(-14);
    var all14   = await interactions.GetRecentAsync(command.UserId, since14, ct);

    if (all14.Count == 0)
        return UpdateNewsProfileResult.NoData;

    var ids      = all14.Select(i => i.NewsItemId).Distinct().ToArray();
    var stored   = await embeddings.GetByNewsItemIdsAsync(ids, embeddingGenerator.ModelKey, ct);
    var embMap   = stored.ToDictionary(e => e.NewsItemId, e => e.Embedding.ToArray());
    var avgDwell = await interactions.GetAverageDwellSecondsAsync(command.UserId, ct)
                   ?? DefaultAverageDwellSeconds;

    // Long-term: blend 7-day interactions with momentum (existing logic)
    var recent7 = all14.Where(i => i.RecordedAt >= DateTimeOffset.UtcNow.AddDays(-7)).ToList();
    var longSignal = ComputeWeightedSum(recent7, embMap, avgDwell);
    if (longSignal is not null)
    {
        var current = profile.LongTermEmbedding.ToArray();
        var blended = Normalize(Blend(Alpha, current, longSignal));
        if (blended is not null)
        {
            profile.LongTermEmbedding = new Vector(blended.Select(d => (float)d).ToArray());
            profile.UpdatedAt = DateTimeOffset.UtcNow;
        }
    }

    // Short-term: raw weighted average of all 14 days, no momentum
    var shortSignal = ComputeWeightedSum(all14, embMap, avgDwell);
    if (shortSignal is not null)
    {
        var normalized = Normalize(shortSignal);
        if (normalized is not null)
        {
            profile.ShortTermEmbedding   = new Vector(normalized.Select(d => (float)d).ToArray());
            profile.ShortTermUpdatedAt   = DateTimeOffset.UtcNow;
        }
    }

    await profiles.UpsertAsync(profile, ct);
    return UpdateNewsProfileResult.Updated;
}
ℹ
One DB read, two outputs. Fetching 14 days of interactions automatically includes the 7-day subset. The existing ComputeWeightedSum helper is called twice with different lists — no duplication of logic.

2. New command — UpdateNewsActiveContextCommand

A separate command reads the user's declared interests via IUserInterestProvider, builds the same seed text that SeedNewsProfileCommandHandler uses, embeds it, and writes the result to ActiveContextEmbedding. It runs on every ingestion cycle — if the user has updated their profile since the last run, the active context embedding immediately reflects the change.

// Platform.Application/Features/News/Profile/UpdateNewsActiveContextCommand.cs
public sealed record UpdateNewsActiveContextCommand(int UserId);

public enum UpdateNewsActiveContextResult { Updated, NoProfile, Error }

// Platform.Application/Features/News/Profile/UpdateNewsActiveContextCommandHandler.cs
public sealed class UpdateNewsActiveContextCommandHandler(
    IValidator<UpdateNewsActiveContextCommand> validator,
    IUserInterestProvider    interestProvider,
    INewsProfileRepository   profiles,
    IMemoryEmbeddingGenerator embeddingGenerator)
{
    public async Task<UpdateNewsActiveContextResult> HandleAsync(
        UpdateNewsActiveContextCommand cmd, CancellationToken ct)
    {
        await validator.ValidateAndThrowAsync(cmd, ct);

        var profile = await profiles.GetAsync(cmd.UserId, ct);
        if (profile is null) return UpdateNewsActiveContextResult.NoProfile;

        var snapshot = await interestProvider.GetInterestsAsync(cmd.UserId, ct);
        var text     = BuildContextText(snapshot);

        var vector = await embeddingGenerator.TryEmbedRecallQueryAsync(text, ct);
        if (vector is null) return UpdateNewsActiveContextResult.Error;

        profile.ActiveContextEmbedding  = new Vector(vector);
        profile.ActiveContextUpdatedAt  = DateTimeOffset.UtcNow;

        await profiles.UpsertAsync(profile, ct);
        return UpdateNewsActiveContextResult.Updated;
    }
}

3. Update NewsVectorSearch — blend at read time

The only change to NewsVectorSearch is in how the query vector is built before the cosine distance ordering. The ranking query itself is unchanged — it still does a single ORDER BY e.Embedding.CosineDistance(qv).

public async Task<IReadOnlyList<NewsVectorHit>> RankByRelevanceAsync(
    int userId, int limit, CancellationToken ct)
{
    var profile = await db.NewsUserProfiles
        .AsNoTracking()
        .FirstOrDefaultAsync(p => p.UserId == userId, ct);

    if (profile is null) return [];

    var lt  = profile.LongTermEmbedding.ToArray();
    var st  = profile.ShortTermEmbedding?.ToArray();
    var ac  = profile.ActiveContextEmbedding?.ToArray();
    var dim = embeddingGenerator.Dimensions;

    var q = new double[dim];
    for (var i = 0; i < dim; i++)
    {
        q[i]  = 0.70 * lt[i];
        q[i] += 0.20 * (st  != null ? st[i]  : lt[i]);
        q[i] += 0.10 * (ac  != null ? ac[i]  : lt[i]);
    }
    var magnitude = Math.Sqrt(q.Sum(x => x * x));
    if (magnitude < 1e-10) return [];
    for (var i = 0; i < dim; i++) q[i] /= magnitude;

    var qv = new Vector(q.Select(d => (float)d).ToArray());
    var modelKey = embeddingGenerator.ModelKey;

    return await db.NewsItemEmbeddings
        .AsNoTracking()
        .Where(e => e.EmbeddingModelKey == modelKey)
        .OrderBy(e => e.Embedding.CosineDistance(qv))
        .Take(limit)
        .Select(e => new NewsVectorHit(
            e.NewsItemId,
            1.0 - (double)e.Embedding.CosineDistance(qv)))
        .ToListAsync(ct);
}

  • Accepts user_id: int

# workers-platform/app/workflows/news_intelligence/activities.py — addition
@activity.defn
async def update_user_news_active_context(user_id: int) -> dict:
    settings = get_settings()
    base     = settings.platform_api_base_url.rstrip("/")
    headers  = {"Authorization": f"Bearer {settings.platform_internal_service_token}"}
    try:
        async with httpx.AsyncClient(timeout=25.0) as client:
            r = await client.post(
                f"{base}/api/internal/v1/news/profile/update-active-context",
                json={"userId": user_id},
                headers=headers,
            )
            r.raise_for_status()
            status = r.json().get("status", "error")
    except Exception:
        logger.exception("update_user_news_active_context failed user_id=%s", user_id)
        status = "error"
    logger.info("update_user_news_active_context user_id=%s status=%s", user_id, status)
    return {"status": status}

Build order and decisions

Step 1
Domain + migration
Add the four fields to NewsUserProfile, configure them in PlatformDbContext, run the EF migration. The DB is ready before any handler touches it.
Step 2
Extend UpdateNewsProfileCommandHandler
Add short-term computation alongside the existing long-term logic. No new files — extend the existing handler. Validate by calling the existing profile/update-from-interactions endpoint and checking that ShortTermEmbedding is now populated.
Step 3
UpdateNewsActiveContextCommandHandler + route
Create the new command, handler, validator. Add the profile/update-active-context internal route and the contract types. Register in DI. Validate by calling the endpoint directly and checking the column.
Step 4
NewsVectorSearch blend
Update the query vector construction in RankByRelevanceAsync. After steps 2 and 3 have populated the new columns, the feed should immediately reflect the 3-way blend without any further wiring.
Step 5
Worker activity + registry
Add update_user_news_active_context to activities.py, call it at the workflow tail in workflow.py, register it in definitions.py. From this point every ingestion run automatically refreshes all three profile components.
!
Decision — blend weights. The 70 / 20 / 10 split is a reasonable starting point but not validated. Short-term at 20% means a week of reading one topic noticeably shifts the feed even when long-term differs. If the feed feels too reactive after testing, reduce short-term to 15% and redistribute to long-term. The weights are constants in NewsVectorSearch — easy to tune without touching the data model.
ℹ
What Phase 5 builds on. Phase 5 adds LLM re-ranking on top of the cosine-ranked candidates Phase 4 produces. The query vector improvements here make the candidate set cleaner — the LLM in Phase 5 starts from better material. No Phase 4 code changes when Phase 5 is added.
